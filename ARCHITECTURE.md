# Architecture

Riverbound is plain JavaScript (ES modules) on Three.js / WebGL 2. It is built with Vite and shipped on desktop in Electron. There is no framework and no engine editor. Content is data-driven (`src/data/*.json`), and all art and audio are generated by code.

```
src/
  main.js              boot: settings → renderer/world → systems → loading → main menu
  Game.js              orchestrator: frame loop, floating origin, system order, atmosphere
  systems.js           installs gameplay systems, interaction providers, UI, audio, debug
  core/                rng (sfc32 + hashes), noise (simplex/fbm/ridged), math, events, Settings, Input
  world/               WorldGen, RegionSequencer, River, Features, terrain/river/scatter meshers,
                       worker pool + worker, Terrain/Vegetation/Content streamers, builders
  water/               WaterSystem, water shader, shared CPU/GPU waves, planar reflection, ripples, wake
  sky/                 TimeOfDay, Celestial (sun/moon/stars), SkyPalette, SkyDome shader
  render/              RenderPipeline, PostFX, presets, dynamic resolution, lighting, global uniforms, materials
  boat/                BoatPhysics (fixed 60 Hz), BoatModel, PlayerBoat, RiverPilot (cruise)
  character/           CharacterModel (joint hierarchy), CharacterAnimator (poses + IK)
  camera/              CameraRig (5 modes with eased transitions)
  weather/             WeatherSystem, GPU precipitation
  wildlife/            Wildlife (flocks, herons, deer, frogs, butterflies, fireflies, fish)
  gameplay/            Session, GameState, SaveSystem, Inventory, Economy, FishingLogic, Fishing, NPCs,
                       Dialogue, Quests, Story, Journal, Upgrades, EventDirector, OnFoot, Interaction
  audio/               AudioEngine (Web Audio), AudioSystem (ambience + effects), Music (generative)
  ui/                  UI manager, HUD, dialogue, menus, panels/*, FishingHUD, PhotoMode, styles.css
  debug/               DebugTools (F3 overlay, console, visualisations, benchmark)
  save/                Storage backends (Electron files / localStorage / memory)
  data/                biomes, storyPlan, story, landmarks, fish, items, upgrades, npcs, lore, events, weather
electron/              desktop shell (main.cjs, preload.cjs)
scripts/               package.mjs (Shipping build + packaging), make-icon.mjs
tests/unit             node:test suites
tests/e2e              Playwright suites, benchmark, packaged-build smoke test
```

## Frame loop (`Game.update`)

1. Poll input.
2. Global actions: camera, cruise, lantern.
3. Advance time (`simDt` is 0 while paused or in frozen photo mode).
4. `preUpdate` of each system (weather).
5. Build the player control: input → river pilot / autopilot. Step the boat physics (fixed 60 Hz sub-steps).
6. `update` of each system, in install order: session, content streamer, wildlife, journal, story, NPCs, event director, on-foot, fishing, interaction, photo, audio, debug.
7. Streaming:
   - terrain quadtree;
   - water ribbons along the river;
   - vegetation cells;
   - a floating-origin check.
8. Visual sync of the boat and character. The atmosphere update builds the sky palette, fog, lights, exposure and god rays.
9. The camera rig update (five modes, eased transitions).
10. Water uniforms (wake, ripples, lights).
11. `lateUpdate` of each system (lightning, UI refresh, debug overlay).
12. Render:
    - planar reflection and ripple pre-passes;
    - an HDR scene target with depth;
    - post (bloom, god rays, DOF, ACES grade, FXAA);
    - dynamic resolution.

`Game.step(dt, frameMs, { render })` is public. The tests use it to simulate minutes of play deterministically without rendering every frame.

## Systems

A system is any object with some of these hooks:

- `init(game)`
- `onWorld(game)`
- `onWorldDispose(game)`
- `preUpdate(dt, game)`
- `update(dt, game)`
- `lateUpdate(dt, game)`
- `setQuality(q)`
- `colliders(x, z, r)`

`game.addSystem()` registers one. Systems talk to each other through the `EventBus` (`game.events`). A few examples:

- `discover`, `fish:caught`, `trade:sell`, `photo:taken`: the story, quests and journal listen to these.
- `music:moment`: stingers from the music system.
- `toast`, `prompt`, `dialogue:show`, `letter`, `caption`: the UI listens to these.

Interactables use a provider pattern. Systems register a function that returns nearby `{ x, z, range, verb, label, action }` entries. `Interaction` picks the best one, shows the prompt and runs its action on **Interact**.

## World and floating origin

All world logic uses absolute metres. The scene graph puts everything under `worldRoot`, which is offset by `-origin`. The origin snaps to 2048 m steps when the player moves more than 1024 m from it, which keeps float precision safe at any distance.

All world-space texture scales in the shaders divide 2048, so patterns don't jump when the origin shifts.

Heavy generation runs in a pool of module Web Workers, each with its own deterministic `WorldGen`: terrain nodes, water ribbons and vegetation scatter. The pool has a priority queue and key-based pruning, so stale requests are dropped when the camera moves on. There is also a synchronous fallback.

## State and saves

`Session` owns the journey state (`GameState.createState`), a single JSON-serialisable object:

- mode and seed;
- coins and inventory;
- upgrades;
- discoveries (places, fish, wildlife, flora, lore, biomes, regions);
- photos (thumbnails);
- quests;
- story (chapter, step, lamps, letters, flags);
- per-NPC and per-settlement relations;
- collected nodes;
- statistics;
- player pose, time and weather.

The **world itself is never saved**: it is a pure function of the seed. That keeps saves small (a few KB plus photo thumbnails) and fully reproducible.

`SaveSystem` has an autosave slot plus three manual slots. Each save has a meta header (mode, chapter, region, play time, date). The save is versioned (`SAVE_VERSION = 3`), and `migrateState` upgrades older saves field by field; the unit tests cover this.

Storage backends:

- **Desktop:** atomic JSON files with `.bak` recovery, through the Electron preload bridge.
- **Browser:** `localStorage`.
- **Tests:** memory.

Settings are stored separately (`settings.json`). They are versioned with their own migration, and default bindings are merged in for newly added actions.

## Rendering pipeline

`RenderPipeline` owns the `WebGLRenderer`, the scene, the camera and these render targets:

- an HDR half-float scene target with a depth texture;
- optional MSAA.

The pre-passes run before the main render:

- **Planar reflection:** a reflected camera at water level. It excludes objects on layer `NO_REFLECT`.
- **Ripple simulation:** a ping-pong height field around the boat.

Environment lighting is a PMREM capture of the procedural sky. It is refreshed on a preset-dependent timer or when forced (time jumps, weather changes).

`PostFX` does bloom (13-tap down/up chain), screen-space god rays (a radial blur of a sun mask), depth of field, an ACES tonemap with grading, vignette, grain, fade and colour-vision modes, and FXAA.

Shared uniforms (time, sun and moon, fog, wind, wetness, lantern, …) live in one object, `G`. A `Material.prototype.onBeforeCompile` hook injects them into every built-in material, and replaces Three.js's fog chunks with height fog, sun in-scatter and distance fog. That is how foliage, terrain, buildings and characters all share one atmosphere.

## Content pipeline (data → world)

- `biomes.json`: climate, neighbours, river and terrain parameters, colours, water, atmosphere, vegetation, weather odds, wildlife, ambience, music, settlement style, landmarks.
- `storyPlan.json`: which story locations must exist, in which biome and region range.
- `landmarks.json`: types, placement rules, names, descriptions.
- `story.json`: chapters and steps (talk / reach / leave / light / read / catch / sell / discover / photo / veil), story characters, letters.
- `fish.json`, `items.json`, `upgrades.json`, `npcs.json`, `lore.json`, `events.json`, `weather.json`: gameplay tables.

`tests/unit/data.test.mjs` checks that every id referenced in these files exists.
